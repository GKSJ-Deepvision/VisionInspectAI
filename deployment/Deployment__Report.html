1. Project Description

VisionInspect AI is a full-stack manufacturing defect detection and quality inspection platform. It lets a quality team upload or simulate product images, inspect them with computer vision, classify defects, calculate severity, generate reports, manage rework, and monitor production quality through dashboards.

In this stage, the development focused on making the user experience responsive across all form factors (mobile devices, factory-floor tablets, and desktop workstations) and establishing a scalable, cloud-deployed, production-style infrastructure. The application transitions from a localized prototype to a fully integrated, live platform using Next.js, FastAPI, MongoDB Atlas, Cloudinary, and Vercel Edge Networks.

2. Core Features

  • Authentication & RBAC: User authentication, registration, admin approval, and role-based access control (Admin, Inspector, Viewer).
  • Inspection Control Room: Manual image inspection, batch inspection, and camera simulation.
  • AI-Powered Visual Pipeline: Image validation, preprocessing, anomaly detection (generating pixel-level anomaly maps), defect classification, and heatmap generation.
  • Severity Scoring Engine: Severity scoring based on defect size, location, defect type, and model confidence.
  • Quality-Control Workflows: Automated pass, fail, review, approve, reject, and rework workflows.
  • Rework Queue System: Rework tickets with priority, assignee, due date, aging, status, and resolution notes.
  • Automated Reporting: PDF inspection reports containing the original image, anomaly heatmap, metadata, reviewer notes, and severity details.
  • Real-time Analytics: Dashboards for tracking inspection counts, defect trends, severity distribution, and line-wise quality.
  • Model Metrics & Calibration: Classifier reports, confusion matrices, threshold tuning, and calibration notes.
  • Managed Storage & Cloud Integration: MongoDB Atlas support for transaction/metadata storage and Cloudinary support for raw images, heatmaps, and reports.

7. Local Setup & Configuration

7.1 Backend and Development Dependencies

Install required packages using PowerShell or Command Prompt:

pip install -r backend/requirements.txt
pip install -r requirements-dev.txt

7.2 Frontend Dependencies

Navigate to the frontend directory and install dependencies:

cd frontend
npm install

7.3 Environment Variables Setup

Create a .env file in the root directory. Use .env.example as the template:

SECRET_KEY=replace-with-secure-secret
FRONTEND_URL=http://localhost:3000
BACKEND_URL=http://localhost:8000
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000

MONGODB_URI=your-mongodb-atlas-uri
MONGODB_DATABASE=visioninspect_ai

CLOUDINARY_CLOUD_NAME=your-cloud-name
CLOUDINARY_API_KEY=your-api-key
CLOUDINARY_API_SECRET=your-api-secret

USE_PADIM_INFERENCE=false
CLASSIFIER_MODEL_PATH=../models/defect_classifier.pkl
MODEL_METADATA_PATH=../models/model_metadata.json
BASELINE_REFERENCE_PATH=../models/inference/normal_reference.png
UPLOAD_DIR=app/uploads

Create frontend/.env.local to point to the local backend API:

NEXT_PUBLIC_API_BASE_URL=http://localhost:8000

7.4 Running the Application Locally

Start the backend (FastAPI):

cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8000

Start the frontend (Next.js):

cd frontend
npm run dev -- --hostname 127.0.0.1 --port 3000

Open the app in your browser:

http://127.0.0.1:3000

8. Model Deployment & Inference Configurations

The project currently supports two primary inference modes:

  • Lightweight Inference Path: A fast live inference path using OpenCV baseline detection combined with the saved classifier artifact (defect_classifier.pkl).
  • PaDiM/Anomalib ML Pipeline: Support for PaDiM (Patch Distribution Modeling) anomaly detection experiments from the machine learning training workflow.
  • Dedicated Compute Serving: In production environments requiring GPU acceleration, host the PaDiM checkpoint on a dedicated compute/model server and set: env USE_PADIM_INFERENCE=true MODEL_CHECKPOINT_PATH=path-or-mounted-location-of-padim-checkpoint
    TIP

    Large checkpoints should be kept outside of GitHub and managed as deployment artifacts.

9.1 Hosting Boundary Details

  • Frontend (Vercel): Serves the Next.js frontend globally via Edge networks for optimal performance and near-zero load times.
  • Backend (Render): Hosts the containerized FastAPI backend. Configured to autoscale on demand.
  • Database (MongoDB Atlas): Managed cloud-based database cluster storing transactional and analytical collections.
  • Media Storage (Cloudinary): High-availability media CDN for visual assets (raw pictures, overlay heatmaps, PDF sheets).
  • GPU Serving: Dedicated compute server is utilized when USE_PADIM_INFERENCE=true is enabled.
NOTE

MongoDB Atlas utilizes IP Whitelisting to enforce network security. Only authorized Render backend nodes can interact with the DB collections. All media assets are transferred securely over HTTPS.

12. Known Limitations & Industry-Ready Notes

  • Simulation Boundaries: PLC, MES, ERP, and industrial camera integrations are currently mock/API-ready simulations rather than direct hardware connections.
  • Dataset Scale: The default workspace contains synthetic sample images for demo purposes; full validation requires loading the complete MVTec dataset locally.
  • Version Control Constraints: Large ML model checkpoints are excluded from Git commits and must be managed as deployment/hosting artifacts.
  • Compute Server Scale: For active production use with PaDiM live inference, a dedicated GPU-backed node is required to prevent latency spikes.
